2.0 INTRODUCTION & THEORETICAL BACKGROUND

In web application architecture, databases serve as the persistent storage layer. Traditionally, developers executed standalone database instances locally (such as mongod running on localhost:27017). While convenient for initial prototyping, local databases lack high availability, automated failover, managed backups, and public network accessibility required for modern web deployments.

Evaluation Metric Local Standalone MongoDB (localhost) MongoDB Atlas Cloud Cluster
High Availability Single point of failure; process crash halts database. 3-node replica set with automated sub-second failover.
Network Reach Restricted to local loopback; external servers blocked. Globally reachable via encrypted TLS 1.3 endpoints.
Disaster Recovery Manual backup scripts required (mongodump). Continuous cloud snapshots and point-in-time recovery.
Access Control Frequently runs unauthenticated in development. Mandatory SCRAM-SHA-256 auth & IP allowlist firewall.

5.0 MONGODB ATLAS CLOUD INFRASTRUCTURE

MongoDB Atlas is an automated Database-as-a-Service (DBaaS) developed by MongoDB Inc. Unlike raw virtual machine hosting, Atlas abstracts all underlying operating system provisioning, storage volume management, patching, replication configuration, and security hardening.

5.1 Replica Set Topology & High Availability

Even within the free M0 Shared tier, Atlas provisions a 3-node replica set comprising one Primary node and two Secondary nodes across distinct fault domains. All write operations (such as inserting a student record) are executed against the Primary node, which records the operation in its idempotent operation log (oplog). Secondary nodes continuously replicate the oplog, ensuring zero data loss if a node encounters hardware failure.

5.2 WiredTiger Storage Engine

The cloud cluster utilizes the WiredTiger engine, featuring document-level concurrency control (multi-version concurrency control - MVCC), prefix compression for B-Tree indexes, and snappy block compression for BSON documents, maximizing I/O throughput.

5.3 Cloud Security Foundations

  • Transport Layer Security: All traffic is enforced over TLS 1.3 encryption on outbound port 27017. Plaintext connections are rejected at the network socket.
  • Network Firewall: A stateful IP Access List denies all traffic by default, blocking packets before reaching the authentication layer.
  • Cryptographic Authentication: Salted Challenge Response Authentication (SCRAM-SHA-256) authenticates users without sending plaintext credentials over the wire.

6.3 Step 3: Database User Security & SCRAM-SHA-256 Authentication

MongoDB Atlas strictly forbids root access or unauthenticated connections. Database users are separate from Atlas cloud console accounts and are authenticated directly by the database engine:

  1. In the Atlas left sidebar, navigate to Security > Database Access.
  2. Click "Add New Database User".
  3. Select Password Authentication (utilizing SCRAM-SHA-256).
  4. Specify a dedicated username, such as dineshparaselli2507_db_user.
  5. Generate a cryptographically strong alphanumeric password (e.g. DineshAtlas#2026).
  6. Role-Based Access Control (RBAC): Under Database User Privileges, assign the built-in role "Read and write to any database" (readWriteAnyDatabase@admin). This grants permission to insert, query, and modify records inside the target database (StudentDB).
  7. Click "Add User" to commit the security credentials to the cluster.

6.4 Step 4: Network Access Security & IP Allowlisting

Atlas enforces an active firewall layer that blocks any IP address not explicitly present on the project's IP Access List:

  1. In the Atlas left sidebar, navigate to Security > Network Access.
  2. Click "Add IP Access List Entry".
  3. Select "Allow Access from Anywhere" (0.0.0.0/0) for dynamic lab and development environments where developer IP addresses change frequently.
  4. Set description: Development allowlist for Express server.
  5. Click "Confirm". The firewall rule transitions from Pending to Active within seconds.

7.0 CONNECTION SEQUENCE FLOW & SRV PROTOCOL ANALYSIS

The DNS Seedlist connection URI utilizing the mongodb+srv:// protocol eliminates hardcoding IP addresses:

Figure 3: Connection Handshake Sequence & Anatomy of the Atlas SRV Connection String

7.1 SRV Connection String Anatomy

mongodb+srv://<username>:<password>@<cluster-url>.mongodb.net/StudentDB?retryWrites=true&w=majority
  • mongodb+srv://: Triggers DNS SRV record queries, allowing the driver to discover all 3 replica set members dynamically without hardcoded hostnames.
  • StudentDB: Explicitly targets the student database namespace.
  • retryWrites=true: Automatically retries write operations if the primary node undergoes a momentary election.
  • w=majority: Enforces majority write concern across replica nodes before returning acknowledgment.

8.2 Database Connection Module: backend/config/db.js

const mongoose = require('mongoose');

mongoose.connection.on('connected', () => console.log('✅ [MongoDB Atlas] Connected to cluster.'));
mongoose.connection.on('error', (err) => console.error('❌ [MongoDB Atlas] Error:', err.message));
mongoose.connection.on('disconnected', () => console.warn('⚠️  [MongoDB Atlas] Disconnected.'));

const connectDB = async () => {
  const uri = process.env.MONGODB_URI;
  const dbName = process.env.DB_NAME || 'StudentDB';

  try {
    const conn = await mongoose.connect(uri, {
      dbName,
      retryWrites: true,
      w: 'majority',
    });
    console.log(`✅ Connected to '${conn.connection.name}' on host: ${conn.connection.host}`);
    return true;
  } catch (error) {
    console.error('❌ Connection failed:', error.message);
    return false;
  }
};
module.exports = { connectDB, getConnectionStatus };

8.3 Student Mongoose Schema: backend/models/studentModel.js

const mongoose = require('mongoose');

const studentSchema = new mongoose.Schema({
  studentId: {
    type: String, required: [true, 'Student ID required'],
    unique: true, trim: true, uppercase: true,
    match: [/^[A-Za-z0-9-]+$/, 'Alphanumeric and hyphens only'],
  },
  name: { type: String, required: [true, 'Name required'], trim: true, minlength: 2 },
  email: {
    type: String, required: [true, 'Email required'],
    unique: true, trim: true, lowercase: true,
    match: [/^\S+@\S+\.\S+$/, 'Valid email required'],
  },
  department: {
    type: String, required: [true, 'Department required'],
    enum: ['Computer Science and Engineering', 'Information Technology',
           'Electronics and Communication Engineering', 'Mechanical Engineering', 'Civil Engineering'],
  },
  year: { type: Number, required: [true, 'Year required'], min: 1, max: 4 },
}, { timestamps: true });

studentSchema.index({ department: 1 });
const Student = mongoose.model('Student', studentSchema, 'students');
module.exports = Student;

8.4 REST Controller Actions: backend/controllers/studentController.js

const Student = require('../models/studentModel');

// @desc Store new student record in Atlas | POST /api/students
const insertStudent = async (req, res) => {
  try {
    const { studentId, name, email, department, year } = req.body;
    const newStudent = await Student.create({ studentId, name, email, department, year: Number(year) });
    res.status(201).json({ success: true, message: 'Stored in MongoDB Atlas', data: newStudent });
  } catch (error) {
    if (error.code === 11000) {
      return res.status(409).json({ success: false, message: 'Duplicate record: studentId or email exists' });
    }
    res.status(400).json({ success: false, message: error.message });
  }
};

// @desc Retrieve all student records from Atlas | GET /api/students
const getAllStudents = async (req, res) => {
  try {
    const students = await Student.find().sort({ createdAt: -1 });
    res.status(200).json({ success: true, count: students.length, data: students });
  } catch (error) {
    res.status(500).json({ success: false, message: error.message });
  }
};

8.6 Express Server Bootstrap: backend/server.js

require('dotenv').config();
const path = require('path');
const express = require('express');
const cors = require('cors');
const { connectDB } = require('./config/db');
const studentRoutes = require('./routes/studentRoutes');

const app = express();
const PORT = process.env.PORT || 5000;

app.use(express.json());
app.use(express.urlencoded({ extended: true }));
app.use(cors());
app.use(express.static(path.join(__dirname, '../frontend')));
app.use('/api', studentRoutes);

app.get('*', (req, res, next) => {
  if (req.path.startsWith('/api')) return next();
  res.sendFile(path.join(__dirname, '../frontend/index.html'));
});

const startServer = async () => {
  await connectDB();
  app.listen(PORT, () => console.log(`🚀 Server running on port ${PORT}`));
};
startServer();
module.exports = app;
